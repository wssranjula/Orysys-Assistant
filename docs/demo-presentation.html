Commercial Bank
AI Assistant

A chat assistant that answers from internal documents — with sources, role-based access, and a visible activity panel so you can see what it is doing.

Problem

Employees have documents.
They need trustworthy answers.

  • Knowledge is spread across policies, runbooks, incidents, and specs
  • A generic chatbot can sound confident but cite nothing
  • Not everyone should see the same information
Solution

One chat. Four specialist helpers. Code keeps it safe.

The user asks a question. A root agent picks the right helper. Each helper can search documents or call approved tools. The final answer includes citations you can check.

How it works

Five steps for every question

  • Check who you are — login, rate limit, block bad input
  • Load memory — remember this conversation
  • Pick a helper — search, research, count, or look up a record
  • Validate the answer — every citation must match real evidence
  • Save & show — stream the reply + activity panel + trace ID
Helpers

Four specialists

  • Knowledge — quick lookup in documents (e.g. “What is the remote-work policy?”)
  • Research — deep search across many docs (e.g. “Summarize last year’s outages”)
  • Analysis — counts and trends (e.g. “How many payment incidents?”)
  • Enterprise — employee, service, and incident records (e.g. “Who owns this service?”)
Roles

Three users. Different access.

Permissions are enforced in code — the agent cannot override them.

Viewer

viewer@commercialbank.test
  • Chat + search internal documents
  • Own department’s confidential docs
  • No analytics, enterprise tools, or restricted docs

Analyst

analyst@commercialbank.test
  • Everything Viewer can do
  • Counts & trends (structured analysis)
  • Employee, service & incident lookups
  • No restricted docs or admin writes

Administrator

admin@commercialbank.test
  • All documents including restricted
  • All tools and enterprise lookups
  • Request incident changes (needs 2nd admin approval)
Viewer Analyst Admin
Chat & search Yes Yes Yes
Analysis & MCP tools No Yes Yes
Restricted documents No No Yes
Approve incident change No No Yes*

*Second administrator must approve — self-approval is blocked (approver@commercialbank.test)

Safety

Built in, not promised in a prompt

  • Roles — see previous slide; same question, different outcome
  • Gateway — every tool call is checked before it runs
  • Citations — the system rejects answers with fake sources
  • Transparency — activity panel shows tools and retrieval, not hidden reasoning
